Taking the assessment tool fully online

How to move the Proficiency Pathway assessment off exported files and onto EY's own Power Platform — sellers assess online, managers calibrate online, leaders see their team live — using SharePoint, Power Apps, Power BI, and row-level security.

The whole idea, in one line

The prototype saves ratings in the browser — which is why data needs a file to travel between a seller and a manager. Swap that one browser store for a single shared SharePoint source everyone signs into, and the file step disappears. Everything else is standard Power Platform.

03 · Experience layer

Power App — two screens, one app

The same experience the prototype demonstrates. The signed-in identity decides which screen and whose data a person gets.

Seller screen

  • Role loads automatically from People by User().Email; pick the review period.
  • Grid of the 24 skills by competency, with a live readiness gauge.
  • Enter Self rating + evidence; Submit writes to Assessments and advances Status.
Can edit: own Self rating & evidence only. Manager/Agreed are read-only.

Manager screen

  • Gallery of direct reports — Filter(People, ManagerEmail = User().Email).
  • Open a report → enter Manager rating, then set the Agreed level and dev actions in calibration.
  • All live to the same data — nothing to email or import.
Can edit: Manager/Agreed & dev actions for their reports. Cannot change a seller's Self rating.
04 · The leader view

The leader view lives inside the app

A pillar leader doesn't go to a separate destination — their team roll-up is a view in the same app, showing only their org. There are two ways to build it; both read the shared data and compute readiness with the workbook formula.

Build option A · Embed Power BI RECOMMENDED

A Power BI tile lives inside the Power App. Best for rich heat maps and a multi-level hierarchy — row-level security walks the whole downline automatically. The leader never leaves the app.

Build option B · Native in Power Apps

Galleries + Power Fx render the roll-up with no Power BI at all — exactly what the prototype's Team View already demonstrates. Scope the reports by ManagerEmail. Simpler to start; less rich for large heat maps.

What the leader sees

  • Competency heat map — people × the 7 competencies + overall.
  • Readiness distribution & movement vs. the prior period.
  • Cadence completion — who's done Self / Manager / Agreed.
  • Aggregate gaps — the skills most often below required.
Readiness % = Σ(Weight × MIN(Agreed, Required)) ÷ Σ(Weight × Required). 100% = meets required on every skill.

How it's scoped to their org

Option A — on People, build the management chain, then filter to the signed-in person plus everyone beneath them:

-- calculated column on People
Path = PATH( People[EmployeeKey], People[ManagerKey] )

-- RLS filter on People ("span of control")
VAR MeKey =
  LOOKUPVALUE( People[EmployeeKey],
    People[EmployeeEmail], USERPRINCIPALNAME() )
RETURN
  PATHCONTAINS( People[Path], MeKey )
Option B — filter the reports gallery by ManagerEmail = User().Email (walk the chain for indirect reports). Either way, a seller sees only their own row.

07 · Straight talk

Dependencies & decisions

The honest short list of what this needs and what to settle before building.

Dependency

The manager-hierarchy feed. RLS is only as good as the People data — someone must own keeping it current, ideally an automated HR/Workday sync.

Design

Edit permissions. A seller edits only their Self column; the manager owns Manager/Agreed. Enforced by app logic + SharePoint permissions — worth designing deliberately.

Decision

Where the app lives. Embed the Power App (and Power BI tile) in Teams or a SharePoint site so entry and the leader view are one place.

Scale

SharePoint fits the pilot and well beyond. If it ever gets very large, Dataverse (also Power Platform) is the heavier-duty backend — not needed to start.

Scope

The prototype can't be the production app. A static page can't do SSO, RLS, or shared writes — so production rebuilds the UX in Power Apps, which is fast because it's already designed and proven.
